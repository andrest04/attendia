# i18n (es + en)

## Objective
Add internationalization to the app with Spanish (default/base) and English, using `react-i18next`.

## Problem / why
All user-visible text (~100 non-test files) is hardcoded Spanish; no i18n library exists. The user wants `es` + `en` only.

## Scope
- Client UI strings, plurals/interpolation, locale-aware date/number formatting (replace hardcoded `es-AR`).
- Language selector persisted in localStorage; `<html lang>` kept in sync.
- Tests run with a global i18n init (`lng: 'es'`, no detector) so existing Spanish assertions keep passing.
- Out of scope for now (decision pending, T7): Spanish messages emitted by `server/*` (`error.explanation`, notification text built in `notificationReconciliation.ts`).

## Constraints
- Stack: React 16, MUI v4, TS 4.6, prettier 1.19.1 (no `import type`/`export type {}`).
- `.ts`/`.tsx` are CRLF; preserve line endings.
- Non-component modules (`presenceView`, `ATTENTION_LEVEL_STYLE`, `PROCTORING_KINDS`, `validateNewClass`, `recordingStateView`) cannot use hooks: return keys or take a `t` argument.
- Spanish copy stays verbatim as the `es` resource (SecurityPage copy is a product decision, do not edit).
- Tests: RED/GREEN where a runnable deterministic test exists; mount/shallow rules per AGENTS.md.
- ~400 authored changed lines per task is a planning heuristic only.

## Delivery strategy
No PRs (user decision). One work-unit commit per task on `feat/i18n`; when checks pass, merge `--no-ff` into local `main` and continue. No push without being asked.
