# AGENTS.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Reference React app demonstrating Twilio Programmable Video + Twilio Conversations, scaffolded with Create React App (TypeScript). Ships with a local Express token server and a Twilio Serverless deployment path via the `@twilio-labs/plugin-rtc` CLI plugin. Requires Node.js >= 22.

## Commands

- `npm start` — runs the local token server (port 8081) and the CRA dev server (port 3000) concurrently. CRA proxies API calls to the token server via `package.json` `proxy`.
- `npm run dev` — CRA dev server only (no token server).
- `npm run server` — token server only (`ts-node` on `server/index.ts`, port 8081).
- `npm run build` — wraps `react-scripts build` via `scripts/build.js` to filter out CRA's "deploy via static server" hint (this app needs the token server).
- `npm run lint` — ESLint on `src` and `server` (config lives in `package.json` under `eslintConfig`, extends `react-app`).
- `npm run typescript:server` — type-checks the server only (`tsc --noEmit -p server/`). The client is type-checked by CRA on build/dev.
- `npm test` — Jest with `TZ=utc` and `jest.config.js` (jsdom environment, ts-jest, enzyme adapter for React 16).
- Run a single test: `npm test -- src/path/to/file.test.tsx` or `npm test -- -t "test name pattern"`.
- `npm run test:ci` — single-run, coverage, JUnit reporter; used in CI. It first runs `scripts/check-focused-tests.js`, which fails on committed `.only` tests.
- `npm run deploy` — `scripts/deploy.sh`: builds the image locally, pushes it to ACR and rolls it out to the Azure Container App (needs `az login`, Docker and the gitignored `scripts/deploy.config`). Refuses a dirty tree (`ALLOW_DIRTY=1`), retries the push, and exits non-zero unless the new revision is ready, runs the pushed image and the public URL answers 200. The runtime image keeps only the packages the compiled server requires (`scripts/server-runtime-deps.js`, roots read from `server-build` requires; `@twilio-labs/plugin-rtc` is copied without its CLI dependencies) — the full `npm ci --omit=dev` is ~1.1 GB of client deps and its layer timed out pushing to ACR.
- `npm run firebase:bootstrap-teacher` — provisions a teacher profile (see `FIREBASE_TEACHER_PROVISIONING.md`).
- `npm run cypress:open` / `npm run cypress:run` — E2E against a real deploy. **These hit live Twilio rooms and conversations and incur charges.**
- `npm run noisecancellation:krisp` — opt-in installer for the Krisp noise-cancellation plugin (copies WASM/weights into `public/noisecancellation`). Run once after `npm install`.
- `npm run storybook` — starts Storybook on port 6006.

`postinstall` copies `@twilio/video-processors` build artifacts into `public/virtualbackground` — required for virtual backgrounds to load at runtime.

## Architecture

### State source of truth
The Twilio Video SDK's `Room` object IS the state — there is no Redux. Components read from `room` and its child objects (which are EventEmitters) by subscribing through hooks. The shared idiom is `useEmitterState` (`src/hooks/useEmitterState`, Observer): it keeps a React value in sync with an emitter, is **handler-based** (tests emit events without mutating the property) and leaves `listenerCount === 0` after unmount — use it instead of hand-writing `useState` + `useEffect` + `on/off`. When connected, `room` is exposed on `window.twilioRoom` for debugging; the chat client/conversation are exposed on `window.chatClient` / `window.chatConversation`.

### Provider tree (`src/index.tsx`)
```
MuiThemeProvider
└─ UnsupportedBrowserWarning
   └─ Router
      └─ AppStateProvider          // auth, settings, recording, gallery, captions, krisp
         └─ Switch (PrivateRoute / LoginPage)
            └─ VideoProvider       // Room, local tracks, screen share, backgrounds
               └─ ParticipantProvider    // ONE shared roster: participants, dominant speaker, screen-share participant
                  └─ ChatProvider  // Conversations client + active conversation
                     └─ AttentionProvider // attention data: live CV behind REACT_APP_ENABLE_ATTENTION_CV, empty otherwise
                        └─ App
```

`VideoProvider` and `ChatProvider` each own a piece of SDK lifecycle and expose it through context. Consumers use `useVideoContext` / `useChatContext` / `useAppState` rather than touching the SDKs directly.

### Two distinct hook layers (don't confuse them)
- `src/hooks/` — general-purpose hooks safe to call anywhere, any number of times (e.g. `useParticipants`, `useDominantSpeaker`, `useLocalAudioToggle`, `useParticipantTile`). The roster hooks read the shared `ParticipantProvider` and fall back to their own subscription without one (tests, Storybook). The reusable building blocks also live here: `useLatest` (latest-value ref for long-lived callbacks), `useOnChange`, `useRequiredContext`, `useAsyncResource` (cancellable one-shot loader), `useReloadableResource` (loader + reload + local edits), `useConfirmDialog` (target kept apart from the open flag so the exit animation doesn't flash). Reach for them before re-implementing the idiom.
- `src/components/VideoProvider/use*` — internal hooks for the `VideoProvider` only. They manage singleton-ish lifecycle (the room, local tracks, screen share, background processor) and **must not be reused elsewhere**. The folder header comment in `VideoProvider/index.tsx` calls this out explicitly.

### Auth (firebase-only)
`firebase` is the only supported auth mode (as of the Feature-0 cleanup that dropped `passcode`/anonymous auth). `src/state/index.tsx` unconditionally calls `useFirebaseAuth()` (Google sign-in or email/password; the ID token is forwarded to the token server and verified by `server/firebaseAuthMiddleware.ts`). `getToken` has exactly ONE implementation (in `useFirebaseAuth`) — there is no auth-mode switch, and `usePasscodeAuth` and the anonymous `getToken`-posts-directly-to-`/token` branch were deleted along with the `deploy:twilio-cli` script (Twilio Serverless Functions cannot run `firebase-admin`, so this app now only deploys as the Express server). All authenticated HTTP goes through one Facade, `createApiClient(user)` (`src/state/useFirebaseAuth/apiClient.ts`: `raw/request/json/blob/send`, auth header + `ClientApiError` parsing in one place); hand-written `fetch` + `Authorization` is only acceptable where a request must outlive the page (`useUnloadReportPersistence`'s keepalive POST) or report upload progress (XHR).

### Token server
`server/index.ts` is the composition root of an Express app. It re-uses the serverless functions shipped inside `@twilio-labs/plugin-rtc/src/serverless/functions/*` for `/token` and `/recordingrules`, adds the Firestore-backed routes (profile + avatar, reports, recordings, resources, classes, notifications, `/completeRoom`, and the public `/rooms/:roomName/open`), and serves the built React app from `../build`. Everything except `/rooms/:roomName/open` is behind `authMiddleware` (`createFirebaseAuthMiddleware(verifyIdToken)`). **Room ownership** (`roomOwnership.ts`) gates the cross-teacher surfaces: `/token` claims `roomOwners/{base64url(roomName)}` = `{uid, roomName, claimedAt}` for a profile-verified teacher; the first `POST /reports` binds `roomSessions/{roomSid}` = `{uid, roomName, boundAt}` (`create()`, first writer wins) after `fetchRoomVia` confirms the SID's Twilio `uniqueName` is the report's room and `roomOwners` names the uid (unknown SID → 404, otherwise mismatch → 403 `room session not owned`); a NEW recording request needs `roomSessions/{sid}.uid === uid` (replays/status/download of existing requests are unchanged, so legacy reports without a session can't start new ones); `/completeRoom` (now on `teacherHandler`) needs `roomOwners/{room_name}.uid === uid`; `/recordingrules` sits behind `createRecordingRulesGuard` (teacher profile + ownership of the room behind `room_sid`). `teacherHandler`'s context also carries `next` (for teacher-only middleware) and an optional `forbiddenMessage`. `loadServerConfig(env)` (`serverConfig.ts`) validates every env var at startup. JSON bodies go through `createJsonBodyParser` (`jsonBodyParser.ts`): the default 100kb limit everywhere, 2mb for `POST /reports` (a 3h class timeline), and a body-parser 413 answered as JSON `{error:{message,explanation}}`; the client's unload keepalive POST is skipped above `MAX_KEEPALIVE_BODY_BYTES` (browser 64 KiB keepalive cap) and the localStorage retry queue carries the report. Handlers are factories — `createXHandler(db, …)` — so the ~250 tests inject fakes; keep those signatures. Teacher-only handlers are a **Template Method**: `teacherHandler(db, {forbiddenExplanation, failure, preValidate?}, work)` (`teacherHandler.ts`) does 401 → role lookup → 403 → `work` → logged 503 inside one try/catch, and a handler supplies only its work and copy; `createTeacherGate(db, options)` is the same skeleton as a pass-through middleware, mounted **before multer** on `POST /resources` (`createResourceUploadTeacherGate`) so a student's upload is refused before it is buffered (the handler keeps its own check). Both multipart uploads cap `files:1, fields:10` (`RESOURCE_UPLOAD_LIMITS`, `AVATAR_UPLOAD_LIMITS`) and their error handlers answer every multer `LIMIT_*` as a JSON 400. The public `/rooms/:roomName/open` is rate-limited per IP (`rateLimit.ts`, `express-rate-limit`, 30/min, JSON 429, in-memory store); Express trusts X-Forwarded-For only when `TRUST_PROXY_HOPS` is set (0-9, validated in `serverConfig.ts`) — set it to 1 behind the Azure Container Apps ingress or every client shares one bucket. Each Gotenberg attempt aborts after 60 s (`attemptTimeoutMs`) and is retried like a connection failure. `GET /classes` returns the newest 200 classes in ascending order; `/notifications/reconcile` reads at most the newest 100 reports / 100 failure episodes and 100 classes from a 7-day look-back (single-field queries, no new index). Shared leaves: `firestoreTime`, `ids`, `base64url`, `ticketSigner`, `http`, `notificationInbox` (Facade over the inbox transaction reads/writes), `twilioGateway` (Adapter/Facade: `roomExistsVia`, `completeRoomVia`, composition lookups), `fileStorageGuards` (`deleteQuietly`, `withUploadCompensation`). `server/index.ts` must keep the literal text `app.post(\n  '/notifications/reconcile',\n  authMiddleware,` — a test reads the file.

### Connection options
`src/utils/useConnectionOptions/useConnectionOptions.ts` builds the `ConnectOptions` passed to `Video.connect` through the pure `buildConnectOptions(settings, platform)` (the hook is a thin wrapper; mobile/dev branches are unit-tested): dominant speaker detection, network quality API, and the bandwidth profile. Track priority is also adjusted dynamically — `VideoTrack` calls `track.setPriority('high')` on mount and resets on unmount so the main video area gets a high-resolution stream. Env flags are read through `src/utils/featureFlags.ts` getters (`isConversationsDisabled()`, `isAttentionCvEnabled()`) **at call time**, never captured at import — tests mutate `process.env`.

### Optional integrations to be aware of
- **Conversations / chat** is opt-out via `REACT_APP_DISABLE_TWILIO_CONVERSATIONS=true`.
- **Krisp noise cancellation** is opt-in (`npm run noisecancellation:krisp`); files are loaded from `public/noisecancellation/` at runtime.
- **Real-Time Transcriptions / captions** require enabling Real-Time Transcriptions in the Twilio Room settings; UI lives under `src/components/TranscriptionsOverlay`.
- **Virtual backgrounds** depend on the post-install copy of `@twilio/video-processors` into `public/virtualbackground/`.

## Classroom layer (built on top of the Twilio reference app)

A Spanish-language classroom domain has been built on top of the base Twilio reference app. The base SDK-as-state pattern is untouched; the classroom layer adds a role concept, role-specific room shells, attention telemetry, a classroom prejoin/auto-rejoin flow, a server-side access guard, and dev-only design surfaces. All in-room UI copy is Spanish.

### Roles & identity
- **Role IS the Twilio identity suffix — there is no server-side role field.** A teacher's display name gets the suffix `[Profesor]` appended at prejoin; that display name becomes the Twilio participant identity.
- `src/classSession/classSessionTypes.ts` — domain helpers/types. `ClassSessionRole = 'teacher' | 'student'`, `TEACHER_DISPLAY_SUFFIX = '[Profesor]'`. `toClassSessionDisplayName(name, role)` appends ` [Profesor]` for teachers (idempotent, case-insensitive). `isTeacherIdentity(identity)` returns true iff the trimmed/lowercased identity **ends with** the suffix — this is the **only** role check used app-wide. Also: `toClassSessionRoomName` (slugify to ASCII kebab, strips accents, fallback `class-session`), `createClassSessionAccess` (builds `{roomName, joinCode, joinLink}`), `normalizeStudentJoinInputToRoomName` (extracts the room slug from a raw code or a full `/room/:name` URL). Committed; tests in `classSessionTypes.test.ts`.
- **The suffix is client-set, but the token server now backs it**: `POST /token` only accepts a teacher-suffixed identity when the verified uid's Firestore profile has `role: 'teacher'` (see *Server-side room-access guard*). The teacher role itself is still self-declared at registration (product decision), so this is not a hard security boundary.

### Attention system
- **REAL CV pipeline, graduated from the lab, OFF by default.** Attention used to be 100% mocked; it is now a real on-device computer-vision pipeline, gated behind the env flag **`REACT_APP_ENABLE_ATTENTION_CV`** (default OFF). With the flag `'true'` and a Room connected the provider is **live** (desktop: local capture + telemetry; phone: `mobile-beacon`, no local capture but real aggregates). Otherwise it hands out an **empty** value — there is **no simulated attention data anywhere** (product decision, 2026-10-18; `mockAttentionData` was deleted). The whole thing was built by graduating the former `/lab/attention` spike (since removed — see Dev-only section) into the real flow in layers: heuristics → capture → transport → provider swap → consent.
- `src/utils/attentionHeuristics.ts` — pure, deterministic, tested CV heuristics (gaze via iris landmarks, head pose pitch/yaw/roll, blink, focus-lost state machine (a discriminated union, `{phase:'ok'} | {phase:'lost', since, counted}`), rolling-window scoring, `createWeightedIndex(weights)` which renormalizes over the signals that are defined, so `computeLabAttentionIndex(eyes,head)` = 4/7·eyes + 3/7·head — posture excluded). Graduated out of `src/components/lab/`; keep it pure (no MediaPipe/React/IO).
- `src/hooks/useAttentionCapture/` — runs MediaPipe **FaceLandmarker** over the Twilio **local** video track at 1 Hz (`SAMPLE_INTERVAL_MS`), CDN WASM, `numFaces:2` for multiface. Returns `{capture,index,components{eyes,head},faces,multiface}`; stays inactive (no MediaPipe load) without a track. Frames go to an offscreen canvas and are discarded — nothing leaves the device. Full WASM/GPU dispose on cleanup. The MediaPipe output goes through the `toFaceFrame` Adapter and the pure `analyzeFrame(state, frame, now)` (`frameAnalysis.ts`); the per-run `disposed` flag in the hook is deliberately a local variable (a shared ref would leak a landmarker and a ghost interval when the track changes mid-load — there is a regression test).
- `src/hooks/useAttentionTelemetry/` — broadcasts each participant's own snapshot at 1 Hz over the **unreliable, unordered** class data channel (latest value wins; a reliable track head-of-line-blocks and collapses the group index under congestion) and aggregates remotes → `RemoteAttention[]` (`{identity,index,multiface,faces,cameraOff,unsupported}`). A `LocalAttentionStatus` (`measuring | camera-off | unsupported`) decides what the local device says: real samples come from the capture loop, the other two are explicit heartbeats so the professor sees "Cámara apagada" / "No medible (celular)" instead of a frozen value. While `measuring` but capture is not active (MediaPipe loading or failed — `useAttentionCapture` then `console.warn`s once) it beats a third heartbeat carrying the additive optional wire field `pending: true` (older receivers ignore it; older senders parse as not pending). A connected student with no telemetry at all is also `pending` (the provider passes the connected identities from `useParticipants` to `buildParticipants`); pending never counts toward the group average, timeline or proctoring. Entries not refreshed within the TTL are swept. It takes an `enabled` parameter and is **fully inert when false** — the provider passes `mode !== 'off'`, so with the CV flag off nobody publishes a telemetry track. Only the number travels, never an image.
- `src/components/AttentionProvider/index.tsx` — one component for every mode (swapping the wrapper per mode would remount the whole app below it). `resolveAttentionMode` (`attentionMode.ts`) decides `off | live | mobile-beacon` from the flag, the room and the device; the rules behind the live data are pure functions in `liveAttention.ts` (who counts as measured, group average, per-student history, the proctoring debounce `stepProctoring`) and the time-driven pieces are the hooks `useAttendanceRoster`, `useGroupTimeline` and `useProctoringFeed`. Proctoring kinds live in one registry (`proctoring.ts`: `PROCTORING_KINDS` + the ordered `DETECTORS` — the order is behaviour). **Live** `AttentionData` = participants from telemetry, real group average, real accumulated timeline, self eyes+head with **posture carried as `-1` = not-measured sentinel** (kept at the storage/UI boundary); in `off` mode it hands out the frozen module-level `EMPTY_VALUE` (same shape, `source:'live'`, no participants/timeline/alerts, `groupDataAvailable:false`, self inactive). `attentionLevel(score)` ranges lowMax=40/mediumMax=70. Level colours/labels come from the single `ATTENTION_LEVEL_STYLE` table (`attentionLevelStyle.ts`; the two different "medium" yellows of the report and the roster are kept as separate fields on purpose). `useAttention()` throws outside the provider. The index uses `computeLabAttentionIndex` (eyes 4/7 + head 3/7, derived from `ATTENTION_WEIGHTS` in `attentionHeuristics.ts`); posture rejoins when it is a measured signal. There is **no** `enabled`/`setEnabled` — students have no control (consent is the gate instead).
- `types.ts` holds all contracts. `source: 'mock' | 'live'` stays wide only because legacy persisted reports carry `'mock'` (the report view, Historial tab and `/history` still tag those as "Datos simulados"); the provider always says `'live'`.
- Three consumption paths: (1) **group gauge** — `ProfessorRoomShell` reads `useAttention()` and feeds `GroupAttentionGauge` + recharts timeline + roster badges + proctoring feed (Individual-tab bar widths use a level→percent lookup 85/60/35, not the raw index); (2) **per-tile overlay** — `GalleryView.tsx` reads `AttentionContext` defensively (tolerates null in tests), builds an identity→{level,multiface,measured} Map **only when teacher** via `toTileAttention` (`GalleryView/tileAttention.ts`; `measured` = `classifyAttention(...) === 'measured'`, so the level badge shows only for a real reading — never for phone / no-face / camera-off / pending students; the multiface flag is unaffected), passes `attention` through `Participant.tsx` to `ParticipantInfo.tsx` (corner badge + multiface flag; local tile never overlaid). Note `GalleryView` now includes the local participant as a regular tile for **everyone** (students reached professor parity; the student-only exclusion was removed). All consumption is **professor-facing**: the student "Mi Atención" panel (`AttentionPanel` + `ToggleAttentionButton` + `isAttentionPanelOpen` in ChatContext) was removed entirely (2026-06-12), and so was the `enabled`/`setEnabled` analysis-pause state — **students have no attention UI and no control over the analysis** (product decision; if a privacy control ever returns, it is a new feature, not a revert). AttentionProvider still nests inside ChatProvider for historical reasons only (the flag that required it is gone); the nesting is vestigial but harmless.
- The professor's reports are **view-only** and come in two flavours that share the pure `AttentionReportView` (data via props) and the normalizers `buildReportViewData.ts` / `storedReportToViewData.ts`: (1) the Grupo-tab "Ver reporte" button opens `LiveReportModal` **in the room**, fed directly from `useAttention()`; (2) the persisted reports (saved to Firestore through `POST /reports` by `useAttentionReportSaver` when the professor leaves or ends the class, with a localStorage retry queue — `pendingAttentionReports.ts`; the saver and the dashboard replay in `useTeacherReports` drop an entry on a permanent rejection, `isPermanentClientError` in `apiClient.ts` = `ClientApiError` 400/403/404/413, and keep it on network errors, 5xx and 401) are listed in the dashboard Historial tab and `/history`, and open in a **NEW TAB** at `/report/:roomSid` — a `PrivateRoute` page (`ReportPage`, no SDK providers) that fetches the report by id with the teacher's token; the server scopes reads to the verified uid. The snapshot is static by design. There are no download/export affordances (PDF/Excel/CSV exporters and the `jspdf`/`jspdf-autotable`/`xlsx` deps were removed, 2026-06-12). `buildAttentionReport.ts` is the pure builder of the persisted payload.

### In-room notifications & raise-hand
- **Toasts via `notistack`** (pinned to **`notistack@1.0.10`** — v2/v3 require MUI v5, this app is MUI v4). `SnackbarProvider` (maxSnack 3, autoHide 4s, top-right, dense) wraps `<App/>` inside `VideoApp` (`src/index.tsx`), so toasts are in-room only and inside the MUI theme.
- `src/hooks/useNotificationToasts/useNotificationToasts.ts` fires a **role-curated** policy so the same raw event surfaces only where it matters. **Student** toasts: professor joins/leaves, "es tu turno", recording on/off. **Professor** toasts: students joining/leaving and raising their hand. Classmate join/leave goes to the student panel (`useShellNotifications`, capped to last 3), NOT toasts; the student's own raise-hand is not toasted (redundant). Prev-value refs are seeded on mount so already-present state never toasts on first render. The old MUI `<Snackbar>` "es tu turno" cue was migrated into this hook. Any test that renders `Room` must `jest.mock('notistack')` (Room calls `useSnackbar`).
- **Class data channel** (`src/hooks/useClassDataChannel/`): the five realtime features — raise-hand, moderation (mute), proctoring warnings, session end and attention telemetry — each call `useClassDataChannel({trackOptions?, onMessage, …})` once; they share ONE ref-counted per-room bus (`classChannelBus.ts`, a Mediator) with one reliable and one unreliable `LocalDataTrack`, and the message union `ClassMessage` + `isAddressedToMe` live in `classProtocol.ts`. The wire format `{type, …}` is a compatibility contract — do not change it. Every consumer filters by `type`. Teacher-to-student commands (`session-ended`, `mute-audio`, `mute-video`, `request-unmute`, `request-video`, `grant-screenshare`, `proctoring-warning`, `grant-turn`) are obeyed only when `isFromTeacher(participant)` (`classProtocol.ts`, wraps `isTeacherIdentity`) holds for the SENDING participant — never trust the payload; raise-hand and telemetry from students stay unfiltered. - **Teacher moderation** (`src/hooks/useModeration/useModeration.ts`, called ONCE in `Room.tsx`): the teacher can force a student's mic off (`mute-audio`) or camera off (`mute-video`, same unpublish path as `ToggleVideoButton` via `useLocalVideoToggle`), and can only SUGGEST turning them on (`request-unmute`, `request-video`; the student accepts or dismisses in `UnmuteRequestPrompt`, which takes `kind: 'mic' | 'camera'`, and enabling happens only from the student's click). `grant-screenshare` gates the student's screen share (`screenShareGrantContext.tsx`, locked by default; held in the teacher's React state, so it is lost on a teacher refresh). **There is deliberately no "expel student" feature** (product decision: it would need a server endpoint plus a ban list, otherwise auto-rejoin brings the student back). Every command is advisory and client-enforced, like the rest of the class channel. Menus: `Room/ModerationMenu/` builds the items as data (`buildStudentModerationItems`, `buildModerationItemsForTarget`) and both the roster row (`RosterList`) and the gallery tile (`TileModerationMenu`, teacher-only, rendered by `ParticipantInfo` only when it gets a `moderation` prop) reuse them; the kebab also appears on speaker-view tiles (`ParticipantStrip`/`ParticipantList` pass `moderation` to remote tiles; `MainParticipantInfo` renders it top-right with `corner="right"`, never on the local participant); Room publishes the handlers and the viewer's `actorRole` through `ModerationActionsContext` (`null` for students). **Hierarchy is hidden**: both teachers show the same "Profesor" label and no "co-profesor" text exists in the UI. `canModerate(actorRole, {isTeacher, isLocal})` (`classProtocol.ts`) is enforced by the SENDER only: owner and co-teacher moderate students, only the confirmed owner moderates a teacher (no screen-share grant on teachers), nobody moderates themselves, and an unknown/loading role fails closed on teachers. `actorRole` comes from `useIsRoomOwner` (`GET /rooms/:roomName/ownership`); receivers do not verify who the owner is. Room always mounts both request prompts so a co-teacher also receives suggestions. Feature log: `odd/tasks/teacher-moderation.md`.

### Prejoin session entry & auto-rejoin
- Replaces Twilio's "type a room name" lobby with a classroom prejoin flow. `src/components/PreJoinScreens/PreJoinScreens.tsx` takes `initialRole` from `useInitialRole` (`TeacherDashboard/useInitialRole.ts`, also used by App.tsx to gate the dashboard): an ordered list of rules run through `firstResolved` — verified profile role → role encoded in a resumable session identity → deep-link `URLRoomName` ⇒ student → `location.state.preJoinRole` (set by LoginPage) → default teacher. The name field is seeded by the same kind of chain. Two-step state machine (roomName → deviceSelection). `RoomNameScreen.tsx` renders two distinct UIs by role (teacher "Crear sesión de clase"; student "Unirme a sala existente"). The student path (`continueAsStudent`) normalizes the typed code/link, probes `checkRoomOpen`, then `replaceUrlWithoutNavigation(...)`s the URL to `/room/:name` (a no-op on a `twil.io` origin / Storybook) so a later refresh can match for auto-rejoin.
- **Auto-rejoin (committed):** a full page refresh destroys the Twilio Room (the source of truth) and would drop the user back to the lobby. `rejoinSession.ts` persists `{roomName, identity}` in **`sessionStorage`** (key `twilio-video-rejoin-session`; survives refresh, tab-scoped, dies on tab close); all reads/writes swallow storage errors. Every browser-storage convenience (`rejoinSession`, `attentionConsent`, `dashboardHandoffSession`, `classSessionContext`, the onboarding flag) is a thin wrapper over `createStorageSlot` (`src/utils/createStorageSlot.ts`), which resolves `window.sessionStorage`/`localStorage` **on every call** (tests swap it) and keeps the exact storage keys — never change a key. `pendingAttentionReports` deliberately stays outside it because its write errors must surface to its callers. `getResumableSession(urlRoomName)` only resumes when the stored `roomName === urlRoomName` (stops a stale tab hijacking a fresh deep link). `useAutoRejoin.ts` seeds `isRejoining` synchronously (no lobby flash), then on mount re-acquires local media (non-fatal on failure), fetches a fresh token for the saved identity, `videoConnect`, and `chatConnect` (unless `REACT_APP_DISABLE_TWILIO_CONVERSATIONS==='true'`). It also watches `AppState.error` because `useRoom`'s connect **resolves (not rejects)** on SDK failure and surfaces via app error state — don't "simplify" this into a try/catch.
- Lifecycle: `DeviceSelectionScreen.handleJoin` calls `saveRejoinSession({roomName, identity:name})` after a successful token fetch (`name` already includes the teacher suffix); `EndCallButton.handleEndCall` calls `clearRejoinSession()` before `room.disconnect()` so an intentional "Salir" does **not** auto-rejoin, whereas a refresh (disconnects via `beforeunload`, not this handler) keeps the session and reconnects. Files (domain modules now live in `src/classSession/`): `src/classSession/rejoinSession.ts`, `rejoinSession.test.ts`, `useAutoRejoin.ts`, plus the changes to `PreJoinScreens.tsx`/`.test.tsx`, `DeviceSelectionScreen.tsx`, `EndCallButton.tsx`, and `src/state/*` are committed.
- **getToken contract changed (committed):** the single `getToken` **rejects** on a non-OK server response, preferring `error.explanation > error.message > statusText` (the room-access guard's localized Spanish message). The outer wrapper in `state/index.tsx` both `setError()`s (app ErrorDialog) **and** re-rejects, so callers must handle the rejection (`DeviceSelectionScreen` adds `.catch(()=>{})`). `MediaErrorSnackbar` handles only getUserMedia/device errors (Spanish copy); `ErrorDialog`'s `enhanceMessage` deliberately recognises a different set of error names.
- **Attention-analysis consent gate (committed):** when `REACT_APP_ENABLE_ATTENTION_CV==='true'`, a **student** (never a teacher) must accept `AttentionConsentModal` before joining — the legal gate for the real CV pipeline. `DeviceSelectionScreen.handleJoin` is split into `doJoin()` (the real token fetch + connect) and a gate: `cvEnabled && !isTeacherIdentity(name) && !hasConsent(roomName)` → opens the modal (no backdrop/escape dismiss); "Aceptar y unirme" → `saveConsent` + `doJoin`, "Volver" → stays on device selection (no join). `attentionConsent.ts` persists consent in `sessionStorage` (key `twilio-video-attention-consent`, room-scoped, error-swallowing, mirrors `rejoinSession`) so auto-rejoin doesn't re-prompt. ### Server-side room-access guard
- **Access gate on `POST /token`.** Twilio creates a room on demand, so whoever requests a token first would create+enter it. The guard stops a student from silently opening a session the teacher never started: a student requesting a token for a room that is not already open gets **HTTP 403** instead of implicitly creating it. A teacher-suffixed identity is accepted only with a teacher **profile** (else 403), and a teacher's token **claims room ownership** (`roomOwners`, below). The teacher role is still self-declared at registration, so this is not a hard security boundary.
- `server/index.ts` wires `app.all('/token', authMiddleware, createRoomAccessGuard(roomExists), tokenEndpoint)`. `/recordingrules` gets `authMiddleware` but **not** the room guard.
- `server/roomAccessGuard.ts` — `createRoomAccessGuard(roomExists, resolveRole = identitySuffixRole, claimRoom?)` — the role comes from a Strategy; production wires `createProfileRoleResolver(firestore)` (suffix + `users/{uid}.role === 'teacher'`; suffix without that profile resolves `'unverified-teacher'` → 403 `teacher role required`). The suffix mirror of `isTeacherIdentity`/`TEACHER_DISPLAY_SUFFIX` **must be kept in sync** with `src/classSession/classSessionTypes.ts` (client and server share no code — `teacherSuffixSync.test.ts` and `roomNameSync.test.ts` pin the mirrors). Rules: no `room_name` → 400 on join-only, else `next()` (the token function rejects it); `create_room===false` (join-only) requires `roomExists` for every role (missing → 403); a teacher then claims ownership via `claimRoom(room_name, uid)` (refused → 403 `room owned by another teacher`); a student needs `roomExists`. Any thrown error → 503 (**fail-closed**). Missing `create_room` is treated as room-creating, so students are gated by default.
- **Room ownership** (`server/roomOwnership.ts`): `roomOwners/{base64url(roomName)}` = `{uid, roomName, claimedAt, refreshedAt}`, claimed in a Firestore transaction by `claimRoomOwnership` when a profile-verified teacher gets a token. Another uid's claim while that room is OPEN in Twilio joins as **co-teacher**: the uid is appended to `roomOwners.coTeachers` and the owner fields/claims history stay untouched (the owner's re-claims keep the list only while the room is still open; reopening a closed room or a takeover resets it). A co-teacher can start/stop recording (`createRecordingRulesGuard` accepts the owner or a recorded co-teacher of the room behind `room_sid`, via `isRoomTeacher`) but NOT end the class (`/completeRoom`), save reports or view/download recordings (`isRoomOwner` / session binder stay owner-only); the client hides end-for-all and report saving for a confirmed co-teacher (`useIsRoomOwner`), keeps the "Grabar" control, and a 403 from `/completeRoom` makes `useSessionEnd` leave quietly with a toast and no `session-ended` broadcast. Co-teachers never count as students (`studentCount`, `studentsOnly` in `AttentionProvider`). If the room is not open, another uid's claim blocks while it is fresh (`FRESH_CLAIM_WINDOW_MS` = 60 s since `max(claimedAt, refreshedAt)` — plugin-rtc creates the room only after the guard, so two simultaneous claims cannot both win); once the class is closed and the claim is stale the name is taken over. **`claimedAt` = when the current uid's ownership began**: set on the first claim and on a takeover, kept on every same-uid re-claim (refresh, auto-rejoin, reopening); `refreshedAt` is bumped on every claim. **Claims history:** every new ownership period also appends `roomOwners/{key}/claims/{autoId}` = `{uid, claimedAt}` in the same transaction (`claimsHistory: true` on the owner doc; a same-uid re-claim of a pre-history doc backfills its period once). The session binder binds a SID to the **owner at room creation** — the latest history entry with `claimedAt <= room.dateCreated + ROOM_CLAIM_CLOCK_SKEW_MS` (5 s; `fetchRoomVia` returns `dateCreated`; single-field query, no composite index) — so a queued report of teacher A still binds after B took the name over, and B cannot bind A's class (403). A room older than every entry → `stale-owner`; an owner doc with no history at all uses the one-off legacy rule (current owner whose `claimedAt` predates the room); unknown times and lookup errors fail closed. `/token` also refuses (400) a `user_identity` with leading/trailing whitespace, so the reserved/checked identity is the exact one plugin-rtc mints. The doc id is base64url because a room name is client input (Firestore rejects `/`, `..`, `__x__` ids). `securityWiring.test.ts` pins the guard chains in `server/index.ts`.
- **Identity reservation** (`server/identityReservation.ts`, mounted on `/token` right after the room guard): `roomIdentities/{base64url(roomName)}.{base64url(identity)}` = `{uid, roomName, identity, reservedAt}`, written in a transaction on every token request (identity trimmed; `.` is outside the base64url alphabet, so the id is unambiguous). Same uid → refresh; another uid → `isParticipantConnectedVia` (`twilioGateway`, `rooms(name).participants(encodeURIComponent(identity)).fetch()`, `status === 'connected'`, 404 → not connected): connected → **409** `identity in use` (Twilio would otherwise kick the real participant), not connected → overwritten for this uid. Any other lookup error → 503 (fail-closed). Requests without a room name or identity pass through to the token function.
- `server/roomExists.ts` — `createRoomExists(twilioClient)` over `twilioGateway.roomExistsVia`, which calls `twilioClient.video.rooms(name).fetch()` (Twilio REST, not plugin-rtc). Success → true; `status===404` → false (the freed uniqueName **is** the "class is closed" signal); any non-404 error rethrown → guard 503. `server/twilioClient.ts` holds the shared `twilioClient` (kept apart from `twilioGateway.ts` so the gateway's pure functions import without credentials). Tests: `server/__tests__/roomAccessGuard.test.ts`, `server/__tests__/roomExists.test.ts`.
- **Deploy parity (removed):** this repo used to also ship `patches/@twilio-labs+plugin-rtc+0.9.0.patch`, porting the same guard into plugin-rtc's serverless `token.js` for the `deploy:twilio-cli` Twilio Serverless deploy path. That script was removed (Feature 0: firebase-only auth needs `firebase-admin`, which Twilio Serverless Functions cannot run — see the Auth section above), so this app no longer deploys via Twilio Serverless and `token.js`'s guard was dead code from this app's perspective. The patch file itself has since been deleted (it was left in place initially, out of scope for that cleanup, and later removed once confirmed unreferenced); `patch-package` and `postinstall` remain wired for the other three still-needed patches (`@material-ui+pickers`, `@mediapipe+tasks-vision`, `react-scripts`).

## Design patterns map (GoF sweep)

The codebase was swept for the classic GoF patterns; this is where they live now, so new code reuses them instead of re-growing the duplication. Where a pattern conflicted with an older note in this file, the pattern's rule wins (e.g. tiles keep `shallow` but assert on extracted leaf components or `.dive()`).

| Pattern | Where | Use it for |
| --- | --- | --- |
| Template Method | `server/teacherHandler.ts`; `Room/ShellLayout/RoomShellLayout.tsx` | a new teacher-only endpoint; a new desktop shell |
| Abstract Factory | `Room/roomShells.tsx` (`roomShellFactory`) | per-role shell + toolbar families (plain functions, not components) |
| Facade | `createApiClient`, `useParticipantTile`, `useScreenShareControl`, `useRecordingToggle`, `useTeacherNotificationApi`, `server/notificationInbox.ts`, `server/twilioGateway.ts` | one entry point over repeated SDK / HTTP / transaction ritual |
| Adapter | `toFaceFrame`, `useEmitterState`, `replaceUrlWithoutNavigation`, `useTeacherNotificationApi` | isolate an awkward third-party or optional API |
| Observer | `useEmitterState`, `useRosterEvents` | keep React in sync with SDK emitters |
| Mediator | `hooks/useClassDataChannel/classChannelBus.ts`, `Room/roomLayout.ts` | one place for cross-feature coordination (data-channel tracks, rail exclusion) |
| Strategy | `identitySuffixRole` / `createProfileRoleResolver`, `resolveAttentionMode`, role toast policies (`useNotificationToasts`), `ROLE_THEME` in `IntroContainer` | swap behaviour/data by role or mode |
| Chain of Responsibility | `firstResolved` (`useInitialRole`, name seed); proctoring `DETECTORS`; `validateNewClass` | ordered rules where the first answer wins |
| Registry / table | `NOTIFICATION_KINDS`, `KIND_RULES`, `PROCTORING_KINDS`, `ATTENTION_LEVEL_STYLE`, `recordingStateView`, `presenceView`, `destinationResolvers`, `routes.ts` | replace parallel `switch`/`if` ladders; adding a case = adding a row |
| Null Object | `NO_CLASS_COMMANDS`, unavailable notification API, absent role-policy handlers | "not available" without `undefined` checks everywhere |
| Decorator | `withFetching` (`state/index.tsx`), `deleteQuietly` / `withUploadCompensation` | cross-cutting loading/error/cleanup around a call |
| Command | `leaveClass`, `useRecordingToggle().toggle`, `useScreenShareControl().toggleScreenShare` | an action reused by several controls |
| State | `FocusLostState`, `stepProctoring`, `classifyAttention`, `resolveScreen` | explicit states instead of sentinel numbers/flags |
| Factory | `createFirebaseAuthMiddleware`, `createTicketSigner`, `createWeightedIndex`, `createStorageSlot` | build configured collaborators; keep globals out of import time |
| Flyweight | `ATTENTION_LEVEL_STYLE` (frozen) | one shared style table |

Considered and **deliberately not done** (so nobody re-adds them): a `UserScope` Firestore facade (≈250 test fakes for little gain); a Singleton/Visitor/Bridge/Prototype/Iterator class hierarchy; splitting `VideoContext`; a shared 1 Hz ticker; `composeProviders`; an `AsyncStateView` component and `useRetryableCommand` (call sites differ in layout and are single-use); splitting `RoomNameScreen` into cards (no shared structure, 500 lines of shallow tests); a shared `classifyMediaError` and a shared initials helper (each surface recognises/derives different things on purpose); `joinGates`/`connectToRoom` (one gate; manual join and auto-rejoin differ in await ordering).

## Testing

- Unit tests: Jest + jsdom + `ts-jest`, with **Enzyme + enzyme-adapter-react-16** (React 16 stack). New tests should follow the existing Enzyme/`@testing-library/react-hooks` patterns rather than introducing a different runner.
- `src/setupTests.ts` polyfills `localStorage`, mocks `@twilio/video-processors` to silence "platform browser already set" warnings, and sets `document.fullscreenEnabled = true`.
- Cypress lives in `cypress/` and uses real Twilio resources — never enable it in automated CI without scoped credentials.
- **Server tests** live under `server/__tests__/` (e.g. `roomAccessGuard.test.ts`, `roomExists.test.ts`); client tests are colocated next to source as `*.test.ts`/`*.test.tsx`.
- **Tiles are `shallow`, shells are `mount`.** `ParticipantInfo`/`MainParticipantInfo` stay on `shallow` and assert on extracted leaf components (`RaisedHandBadge`, `ReconnectingOverlay`) — never `mount` them. The room shells (`ProfessorRoomShell`, `StudentRoomShell`) are rendered through `RoomShellLayout`/`CollapsibleRail` slots, so their tests `mount` (host markup only exists once the layout renders). Toolbar tests `.dive()` into `OverflowMenu` (`wrapper.find('OverflowMenu').dive()`) to reach the kebab and its items.
- **Hermetic page tests.** `useAppState` is mocked globally, so a page left mounted by an earlier test re-renders against a later test's mock — unmount wrappers in `afterEach` (see `RecordingViewerPage.test.tsx`). Hooks that take a loader (`useAsyncResource`, `useReloadableResource`) key their effect on the loader's identity: memoize it, and in tests don't create a fresh `jest.fn` per render if the call count matters.
- **Pure first.** New rules go in pure functions with an injected clock (`validateNewClass`, `resolveScreen`, `roomLayoutReducer`, `stepProctoring`, `classifyAttention`) and are tested without React.
- **prettier 1.19.1 gotcha:** the pre-commit hook (husky + lint-staged → prettier **1.19.1**) **cannot parse type-only re-export/import syntax** — `export type { X } from './y'` and `import type { ... }` will fail the hook. Barrel files (`index.ts`) must therefore import types **directly** from their source module rather than re-exporting them as `export type`. The `ProfessorRoomShell` barrel does this: `Room.tsx` imports the `ProfessorRightTab` type directly from `./ProfessorRoomShell/ProfessorRoomShell`, not from the barrel.
