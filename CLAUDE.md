# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Reference React app demonstrating Twilio Programmable Video + Twilio Conversations, scaffolded with Create React App (TypeScript). Ships with a local Express token server and a Twilio Serverless deployment path via the `@twilio-labs/plugin-rtc` CLI plugin. Requires Node.js >= 22.

## Commands

- `npm start` — runs the local token server (port 8081) and the CRA dev server (port 3000) concurrently. CRA proxies API calls to the token server via `package.json` `proxy`.
- `npm run dev` — CRA dev server only (no token server).
- `npm run server` — token server only (`ts-node` on `server/index.ts`, port 8081).
- `npm run build` — wraps `react-scripts build` via `scripts/build.js` to filter out CRA's "deploy via static server" hint (this app needs the token server).
- `npm run lint` — ESLint on `src` and `server` (config lives in `package.json` under `eslintConfig`, extends `react-app`).
- `npm run typescript:server` — type-checks the server only (`tsc --noEmit -p server/`). The client is type-checked by CRA on build/dev.
- `npm test` — Jest with `TZ=utc` and `jest.config.js` (jsdom environment, ts-jest, enzyme adapter for React 16).
- Run a single test: `npm test -- src/path/to/file.test.tsx` or `npm test -- -t "test name pattern"`.
- `npm run test:ci` — single-run, coverage, JUnit reporter; used in CI.
- `npm run cypress:open` / `npm run cypress:run` — E2E against a real deploy. **These hit live Twilio rooms and conversations and incur charges.**
- `npm run noisecancellation:krisp` — opt-in installer for the Krisp noise-cancellation plugin (copies WASM/weights into `public/noisecancellation`). Run once after `npm install`.
- `npm run storybook` — starts Storybook on port 6006.

`postinstall` copies `@twilio/video-processors` build artifacts into `public/virtualbackground` — required for virtual backgrounds to load at runtime.

## Architecture

### State source of truth
The Twilio Video SDK's `Room` object IS the state — there is no Redux. Components read from `room` and its child objects (which are EventEmitters) by subscribing through hooks. The shared idiom is `useEmitterState` (`src/hooks/useEmitterState`, Observer): it keeps a React value in sync with an emitter, is **handler-based** (tests emit events without mutating the property) and leaves `listenerCount === 0` after unmount — use it instead of hand-writing `useState` + `useEffect` + `on/off`. When connected, `room` is exposed on `window.twilioRoom` for debugging; the chat client/conversation are exposed on `window.chatClient` / `window.chatConversation`.

### Provider tree (`src/index.tsx`)
```
MuiThemeProvider
└─ UnsupportedBrowserWarning
   └─ Router
      └─ AppStateProvider          // auth, settings, recording, gallery, captions, krisp
         └─ Switch (PrivateRoute / LoginPage)
            └─ VideoProvider       // Room, local tracks, screen share, backgrounds
               └─ ParticipantProvider    // ONE shared roster: participants, dominant speaker, screen-share participant
                  └─ ChatProvider  // Conversations client + active conversation
                     └─ AttentionProvider // attention data: live CV behind REACT_APP_ENABLE_ATTENTION_CV, mock otherwise
                        └─ App
```

`VideoProvider` and `ChatProvider` each own a piece of SDK lifecycle and expose it through context. Consumers use `useVideoContext` / `useChatContext` / `useAppState` rather than touching the SDKs directly.

### Two distinct hook layers (don't confuse them)
- `src/hooks/` — general-purpose hooks safe to call anywhere, any number of times (e.g. `useParticipants`, `useDominantSpeaker`, `useLocalAudioToggle`, `useParticipantTile`). The roster hooks read the shared `ParticipantProvider` and fall back to their own subscription without one (tests, Storybook). The reusable building blocks also live here: `useLatest` (latest-value ref for long-lived callbacks), `useOnChange`, `useRequiredContext`, `useAsyncResource` (cancellable one-shot loader), `useReloadableResource` (loader + reload + local edits), `useConfirmDialog` (target kept apart from the open flag so the exit animation doesn't flash). Reach for them before re-implementing the idiom.
- `src/components/VideoProvider/use*` — internal hooks for the `VideoProvider` only. They manage singleton-ish lifecycle (the room, local tracks, screen share, background processor) and **must not be reused elsewhere**. The folder header comment in `VideoProvider/index.tsx` calls this out explicitly.

### Auth (firebase-only)
`firebase` is the only supported auth mode (as of the Feature-0 cleanup that dropped `passcode`/anonymous auth). `src/state/index.tsx` unconditionally calls `useFirebaseAuth()` (Google sign-in or email/password; the ID token is forwarded to the token server and verified by `server/firebaseAuthMiddleware.ts`). `getToken` has exactly ONE implementation (in `useFirebaseAuth`) — there is no auth-mode switch, and `usePasscodeAuth` and the anonymous `getToken`-posts-directly-to-`/token` branch were deleted along with the `deploy:twilio-cli` script (Twilio Serverless Functions cannot run `firebase-admin`, so this app now only deploys as the Express server). All authenticated HTTP goes through one Facade, `createApiClient(user)` (`src/state/useFirebaseAuth/apiClient.ts`: `raw/request/json/blob/send`, auth header + `ClientApiError` parsing in one place); hand-written `fetch` + `Authorization` is only acceptable where a request must outlive the page (`useUnloadReportPersistence`'s keepalive POST) or report upload progress (XHR).

### Token server
`server/index.ts` is the composition root of an Express app. It re-uses the serverless functions shipped inside `@twilio-labs/plugin-rtc/src/serverless/functions/*` for `/token` and `/recordingrules`, adds the Firestore-backed routes (profile + avatar, reports, recordings, resources, classes, notifications, `/completeRoom`, and the public `/rooms/:roomName/open`), and serves the built React app from `../build`. Everything except `/rooms/:roomName/open` is behind `authMiddleware` (`createFirebaseAuthMiddleware(verifyIdToken)`). `loadServerConfig(env)` (`serverConfig.ts`) validates every env var at startup. Handlers are factories — `createXHandler(db, …)` — so the ~250 tests inject fakes; keep those signatures. Teacher-only handlers are a **Template Method**: `teacherHandler(db, {forbiddenExplanation, failure, preValidate?}, work)` (`teacherHandler.ts`) does 401 → role lookup → 403 → `work` → logged 503 inside one try/catch, and a handler supplies only its work and copy. Shared leaves: `firestoreTime`, `ids`, `base64url`, `ticketSigner`, `http`, `notificationInbox` (Facade over the inbox transaction reads/writes), `twilioGateway` (Adapter/Facade: `roomExistsVia`, `completeRoomVia`, composition lookups), `fileStorageGuards` (`deleteQuietly`, `withUploadCompensation`). `server/index.ts` must keep the literal text `app.post(\n  '/notifications/reconcile',\n  authMiddleware,` — a test reads the file.

### Connection options
`src/utils/useConnectionOptions/useConnectionOptions.ts` builds the `ConnectOptions` passed to `Video.connect` through the pure `buildConnectOptions(settings, platform)` (the hook is a thin wrapper; mobile/dev branches are unit-tested): dominant speaker detection, network quality API, and the bandwidth profile. Track priority is also adjusted dynamically — `VideoTrack` calls `track.setPriority('high')` on mount and resets on unmount so the main video area gets a high-resolution stream. Env flags are read through `src/utils/featureFlags.ts` getters (`isConversationsDisabled()`, `isAttentionCvEnabled()`) **at call time**, never captured at import — tests mutate `process.env`.

### Optional integrations to be aware of
- **Conversations / chat** is opt-out via `REACT_APP_DISABLE_TWILIO_CONVERSATIONS=true`.
- **Krisp noise cancellation** is opt-in (`npm run noisecancellation:krisp`); files are loaded from `public/noisecancellation/` at runtime.
- **Real-Time Transcriptions / captions** require enabling Real-Time Transcriptions in the Twilio Room settings; UI lives under `src/components/TranscriptionsOverlay`.
- **Virtual backgrounds** depend on the post-install copy of `@twilio/video-processors` into `public/virtualbackground/`.

## Classroom layer (built on top of the Twilio reference app)

A Spanish-language classroom domain has been built on top of the base Twilio reference app. The base SDK-as-state pattern is untouched; the classroom layer adds a role concept, role-specific room shells, attention telemetry, a classroom prejoin/auto-rejoin flow, a server-side access guard, and dev-only design surfaces. All in-room UI copy is Spanish.

### Roles & identity
- **Role IS the Twilio identity suffix — there is no server-side role field.** A teacher's display name gets the suffix `[Profesor]` appended at prejoin; that display name becomes the Twilio participant identity.
- `src/components/PreJoinScreens/classSessionTypes.ts` — domain helpers/types. `ClassSessionRole = 'teacher' | 'student'`, `TEACHER_DISPLAY_SUFFIX = '[Profesor]'`. `toClassSessionDisplayName(name, role)` appends ` [Profesor]` for teachers (idempotent, case-insensitive). `isTeacherIdentity(identity)` returns true iff the trimmed/lowercased identity **ends with** the suffix — this is the **only** role check used app-wide. Also: `toClassSessionRoomName` (slugify to ASCII kebab, strips accents, fallback `class-session`), `createClassSessionAccess` (builds `{roomName, joinCode, joinLink}`), `normalizeStudentJoinInputToRoomName` (extracts the room slug from a raw code or a full `/room/:name` URL). Committed; tests in `classSessionTypes.test.ts`.
- **This is a client-set value with NO server enforcement** — trivially spoofable, a UX guardrail, not a security boundary (see project memory "Room-access gate is a guardrail").

### Attention system
- **REAL CV pipeline, graduated from the lab, OFF by default.** Attention used to be 100% mocked; it is now a real on-device computer-vision pipeline, gated behind the env flag **`REACT_APP_ENABLE_ATTENTION_CV`** (default OFF → mock fallback). The provider goes **live** only when the flag is `'true'` AND a Room is connected AND the device is desktop; otherwise it falls back to `mockAttentionData`. The whole thing was built by graduating the former `/lab/attention` spike (since removed — see Dev-only section) into the real flow in layers: heuristics → capture → transport → provider swap → consent.
- `src/utils/attentionHeuristics.ts` — pure, deterministic, tested CV heuristics (gaze via iris landmarks, head pose pitch/yaw/roll, blink, focus-lost state machine (a discriminated union, `{phase:'ok'} | {phase:'lost', since, counted}`), rolling-window scoring, `createWeightedIndex(weights)` which renormalizes over the signals that are defined, so `computeLabAttentionIndex(eyes,head)` = 4/7·eyes + 3/7·head — posture excluded). Graduated out of `src/components/lab/`; keep it pure (no MediaPipe/React/IO).
- `src/hooks/useAttentionCapture/` — runs MediaPipe **FaceLandmarker** over the Twilio **local** video track at 1 Hz (`SAMPLE_INTERVAL_MS`), CDN WASM, `numFaces:2` for multiface. Returns `{capture,index,components{eyes,head},faces,multiface}`; stays inactive (no MediaPipe load) without a track. Frames go to an offscreen canvas and are discarded — nothing leaves the device. Full WASM/GPU dispose on cleanup. The MediaPipe output goes through the `toFaceFrame` Adapter and the pure `analyzeFrame(state, frame, now)` (`frameAnalysis.ts`); the per-run `disposed` flag in the hook is deliberately a local variable (a shared ref would leak a landmarker and a ghost interval when the track changes mid-load — there is a regression test).
- `src/hooks/useAttentionTelemetry/` — broadcasts each participant's own snapshot at 1 Hz over the **unreliable, unordered** class data channel (latest value wins; a reliable track head-of-line-blocks and collapses the group index under congestion) and aggregates remotes → `RemoteAttention[]` (`{identity,index,multiface,faces,cameraOff,unsupported}`). A `LocalAttentionStatus` (`measuring | camera-off | unsupported`) decides what the local device says: real samples come from the capture loop, the other two are explicit heartbeats so the professor sees "Cámara apagada" / "No medible (celular)" instead of a frozen value. Entries not refreshed within the TTL are swept. It takes an `enabled` parameter and is **fully inert when false** — the provider passes `mode !== 'mock'`, so with the CV flag off nobody publishes a telemetry track. Only the number travels, never an image.
- `src/components/AttentionProvider/index.tsx` — one component for every mode (swapping the wrapper per mode would remount the whole app below it). `resolveAttentionMode` (`attentionMode.ts`) decides `mock | live | mobile-beacon` from the flag, the room and the device; the rules behind the live data are pure functions in `liveAttention.ts` (who counts as measured, group average, per-student history, the proctoring debounce `stepProctoring`) and the time-driven pieces are the hooks `useAttendanceRoster`, `useGroupTimeline` and `useProctoringFeed`. Proctoring kinds live in one registry (`proctoring.ts`: `PROCTORING_KINDS` + the ordered `DETECTORS` — the order is behaviour). **Live** `AttentionData` = participants from telemetry, real group average, real accumulated timeline, self eyes+head with **posture carried as `-1` = not-measured sentinel** (kept at the storage/UI boundary); otherwise it hands out the memoized `MOCK_VALUE` built from `mockAttentionData`. `attentionLevel(score)` ranges lowMax=40/mediumMax=70. Level colours/labels come from the single `ATTENTION_LEVEL_STYLE` table (`attentionLevelStyle.ts`; the two different "medium" yellows of the report and the roster are kept as separate fields on purpose). `useAttention()` throws outside the provider. Live index uses `computeLabAttentionIndex`; `attentionFormula.ts` `computeAttentionIndex` (clamp(0.40·eyes + 0.30·posture + 0.30·head)) serves **only the mock fallback** until posture is a measured signal. There is **no** `enabled`/`setEnabled` — students have no control (consent is the gate instead).
- `src/components/AttentionProvider/mockAttentionData.ts` — deterministic mock (no `Math.random`/`Date.now`): `groupAttention=72`, `attentionThreshold=60`, 11-point timeline, 5 participants, 2 proctoring alerts, `source:'mock'`. Still the **fallback** value when the pipeline is off. `types.ts` holds all contracts.
- Three consumption paths: (1) **group gauge** — `ProfessorRoomShell` reads `useAttention()` and feeds `GroupAttentionGauge` + recharts timeline + roster badges + proctoring feed (shows a "Datos simulados — pipeline CV pendiente" tag when `source==='mock'`; Individual-tab bar widths use a level→percent lookup 85/60/35, not the raw index); (2) **per-tile overlay** — `GalleryView.tsx` reads `AttentionContext` defensively (tolerates null in tests), builds an identity→{level,multiface} Map **only when teacher**, passes `attention` through `Participant.tsx` to `ParticipantInfo.tsx` (corner badge + multiface flag; local tile never overlaid). Note `GalleryView` now includes the local participant as a regular tile for **everyone** (students reached professor parity; the student-only exclusion was removed). All consumption is **professor-facing**: the student "Mi Atención" panel (`AttentionPanel` + `ToggleAttentionButton` + `isAttentionPanelOpen` in ChatContext) was removed entirely (2026-06-12), and so was the `enabled`/`setEnabled` analysis-pause state — **students have no attention UI and no control over the analysis** (product decision; if a privacy control ever returns, it is a new feature, not a revert). AttentionProvider still nests inside ChatProvider for historical reasons only (the flag that required it is gone); the nesting is vestigial but harmless.
- The professor's reports are **view-only** and come in two flavours that share the pure `AttentionReportView` (data via props) and the normalizers `buildReportViewData.ts` / `storedReportToViewData.ts`: (1) the Grupo-tab "Ver reporte" button opens `LiveReportModal` **in the room**, fed directly from `useAttention()`; (2) the persisted reports (saved to Firestore through `POST /reports` by `useAttentionReportSaver` when the professor leaves or ends the class, with a localStorage retry queue — `pendingAttentionReports.ts`) are listed in the dashboard Historial tab and `/history`, and open in a **NEW TAB** at `/report/:roomSid` — a `PrivateRoute` page (`ReportPage`, no SDK providers) that fetches the report by id with the teacher's token; the server scopes reads to the verified uid. The snapshot is static by design. There are no download/export affordances (PDF/Excel/CSV exporters and the `jspdf`/`jspdf-autotable`/`xlsx` deps were removed, 2026-06-12). `buildAttentionReport.ts` is the pure builder of the persisted payload.

### In-room notifications & raise-hand
- **Toasts via `notistack`** (pinned to **`notistack@1.0.10`** — v2/v3 require MUI v5, this app is MUI v4). `SnackbarProvider` (maxSnack 3, autoHide 4s, top-right, dense) wraps `<App/>` inside `VideoApp` (`src/index.tsx`), so toasts are in-room only and inside the MUI theme.
- `src/hooks/useNotificationToasts/useNotificationToasts.ts` fires a **role-curated** policy so the same raw event surfaces only where it matters. **Student** toasts: professor joins/leaves, "es tu turno", recording on/off. **Professor** toasts: students joining/leaving and raising their hand. Classmate join/leave goes to the student panel (`useShellNotifications`, capped to last 3), NOT toasts; the student's own raise-hand is not toasted (redundant). Prev-value refs are seeded on mount so already-present state never toasts on first render. The old MUI `<Snackbar>` "es tu turno" cue was migrated into this hook. Any test that renders `Room` must `jest.mock('notistack')` (Room calls `useSnackbar`).
- **Class data channel** (`src/hooks/useClassDataChannel/`): the five realtime features — raise-hand, moderation (mute), proctoring warnings, session end and attention telemetry — each call `useClassDataChannel({trackOptions?, onMessage, …})` once; they share ONE ref-counted per-room bus (`classChannelBus.ts`, a Mediator) with one reliable and one unreliable `LocalDataTrack`, and the message union `ClassMessage` + `isAddressedToMe` live in `classProtocol.ts`. The wire format `{type, …}` is a compatibility contract — do not change it. Every consumer filters by `type`.
- **Raise-hand badge** — when a participant raises their hand, a hand badge (white circle + dark `PanToolIcon`) shows in the **bottom-right of their tile**. `useRaiseHand` stays a SINGLETON hook called once in `Room.tsx`; Room derives a `Set<string>` of raised identities (remote `raisedHands` + local when `isHandRaised`) via `buildRaisedHandIdentities` and provides it through `RaisedHandsContext` (`src/hooks/useRaiseHand/raisedHandsContext.ts`). `ParticipantInfo.tsx` and `MainParticipantInfo.tsx` read it through `useParticipantTile` (which calls `useRaisedHand(identity)` — extracted so component tests mock it and stay on `shallow`) and render the `RaisedHandBadge` leaf. Do NOT `mount` those tiles; they fire real `useTrack`/`useScreenShareParticipant` effects — assert on the leaf component (`wrapper.find(RaisedHandBadge)`) or `.dive()` into it. Default empty set → tiles render fine without a provider.

### Prejoin session entry & auto-rejoin
- Replaces Twilio's "type a room name" lobby with a classroom prejoin flow. `src/components/PreJoinScreens/PreJoinScreens.tsx` takes `initialRole` from `useInitialRole` (`TeacherDashboard/useInitialRole.ts`, also used by App.tsx to gate the dashboard): an ordered list of rules run through `firstResolved` — verified profile role → role encoded in a resumable session identity → deep-link `URLRoomName` ⇒ student → `location.state.preJoinRole` (set by LoginPage) → default teacher. The name field is seeded by the same kind of chain. Two-step state machine (roomName → deviceSelection). `RoomNameScreen.tsx` renders two distinct UIs by role (teacher "Crear sesión de clase"; student "Unirme a sala existente"). The student path (`continueAsStudent`) normalizes the typed code/link, probes `checkRoomOpen`, then `replaceUrlWithoutNavigation(...)`s the URL to `/room/:name` (a no-op on a `twil.io` origin / Storybook) so a later refresh can match for auto-rejoin.
- **Auto-rejoin (committed):** a full page refresh destroys the Twilio Room (the source of truth) and would drop the user back to the lobby. `rejoinSession.ts` persists `{roomName, identity}` in **`sessionStorage`** (key `twilio-video-rejoin-session`; survives refresh, tab-scoped, dies on tab close); all reads/writes swallow storage errors. Every browser-storage convenience (`rejoinSession`, `attentionConsent`, `dashboardHandoffSession`, `classSessionContext`, the onboarding flag) is a thin wrapper over `createStorageSlot` (`src/utils/createStorageSlot.ts`), which resolves `window.sessionStorage`/`localStorage` **on every call** (tests swap it) and keeps the exact storage keys — never change a key. `pendingAttentionReports` deliberately stays outside it because its write errors must surface to its callers. `getResumableSession(urlRoomName)` only resumes when the stored `roomName === urlRoomName` (stops a stale tab hijacking a fresh deep link). `useAutoRejoin.ts` seeds `isRejoining` synchronously (no lobby flash), then on mount re-acquires local media (non-fatal on failure), fetches a fresh token for the saved identity, `videoConnect`, and `chatConnect` (unless `REACT_APP_DISABLE_TWILIO_CONVERSATIONS==='true'`). It also watches `AppState.error` because `useRoom`'s connect **resolves (not rejects)** on SDK failure and surfaces via app error state — don't "simplify" this into a try/catch.
- Lifecycle: `DeviceSelectionScreen.handleJoin` calls `saveRejoinSession({roomName, identity:name})` after a successful token fetch (`name` already includes the teacher suffix); `EndCallButton.handleEndCall` calls `clearRejoinSession()` before `room.disconnect()` so an intentional "Salir" does **not** auto-rejoin, whereas a refresh (disconnects via `beforeunload`, not this handler) keeps the session and reconnects. Files: `rejoinSession.ts`, `rejoinSession.test.ts`, `useAutoRejoin.ts`, plus the changes to `PreJoinScreens.tsx`/`.test.tsx`, `DeviceSelectionScreen.tsx`, `EndCallButton.tsx`, and `src/state/*` are committed.
- **getToken contract changed (committed):** the single `getToken` **rejects** on a non-OK server response, preferring `error.explanation > error.message > statusText` (the room-access guard's localized Spanish message). The outer wrapper in `state/index.tsx` both `setError()`s (app ErrorDialog) **and** re-rejects, so callers must handle the rejection (`DeviceSelectionScreen` adds `.catch(()=>{})`). `MediaErrorSnackbar` handles only getUserMedia/device errors (Spanish copy); `ErrorDialog`'s `enhanceMessage` deliberately recognises a different set of error names.
- **Attention-analysis consent gate (committed):** when `REACT_APP_ENABLE_ATTENTION_CV==='true'`, a **student** (never a teacher) must accept `AttentionConsentModal` before joining — the legal gate for the real CV pipeline. `DeviceSelectionScreen.handleJoin` is split into `doJoin()` (the real token fetch + connect) and a gate: `cvEnabled && !isTeacherIdentity(name) && !hasConsent(roomName)` → opens the modal (no backdrop/escape dismiss); "Aceptar y unirme" → `saveConsent` + `doJoin`, "Volver" → stays on device selection (no join). `attentionConsent.ts` persists consent in `sessionStorage` (key `twilio-video-attention-consent`, room-scoped, error-swallowing, mirrors `rejoinSession`) so auto-rejoin doesn't re-prompt. The modal copy lists only what is actually measured (gaze + head, **not** posture) and only mounts when the flag is on; flag off → no prompt, normal join. Product decisions: prejoin-time, accept-or-go-back, **fixed at entry** (no in-room revocation UI).

### Server-side room-access guard
- **Honest-flow gate on `POST /token` (committed).** Twilio creates a room on demand, so whoever requests a token first would create+enter it. The guard stops a student from silently opening a session the teacher never started: a student requesting a token for a room that is not already open gets **HTTP 403** instead of implicitly creating it. Teachers are always allowed; this is **explicitly a UX guardrail, NOT a security boundary** (role is the client-set identity suffix).
- `server/index.ts` wires `app.all('/token', authMiddleware, createRoomAccessGuard(roomExists), tokenEndpoint)`. `/recordingrules` gets `authMiddleware` but **not** the room guard.
- `server/roomAccessGuard.ts` — `createRoomAccessGuard(roomExists, resolveRole = identitySuffixRole)` — the role comes from a Strategy, today `identitySuffixRole`, which holds a server-side mirror of `isTeacherIdentity`/`TEACHER_DISPLAY_SUFFIX` (**must be kept in sync** with `classSessionTypes.ts`; client and server share no code — `teacherSuffixSync.test.ts` and `roomNameSync.test.ts` pin the mirrors). Swap the resolver (e.g. a Firestore-profile role) without touching the guard. Passes through without checking when `create_room===false`, identity is a teacher, or `room_name` is missing; otherwise awaits `roomExists(room_name)`: exists → `next()`; missing → 403 (Spanish explanation); thrown error → 503 (**fail-closed**). Missing `create_room` is treated as room-creating, so students are gated by default.
- `server/roomExists.ts` — `createRoomExists(twilioClient)` over `twilioGateway.roomExistsVia`, which calls `twilioClient.video.rooms(name).fetch()` (Twilio REST, not plugin-rtc). Success → true; `status===404` → false (the freed uniqueName **is** the "class is closed" signal); any non-404 error rethrown → guard 503. `server/twilioClient.ts` holds the shared `twilioClient` (kept apart from `twilioGateway.ts` so the gateway's pure functions import without credentials). Tests: `server/__tests__/roomAccessGuard.test.ts`, `server/__tests__/roomExists.test.ts`.
- **Deploy parity (removed):** this repo used to also ship `patches/@twilio-labs+plugin-rtc+0.9.0.patch`, porting the same guard into plugin-rtc's serverless `token.js` for the `deploy:twilio-cli` Twilio Serverless deploy path. That script was removed (Feature 0: firebase-only auth needs `firebase-admin`, which Twilio Serverless Functions cannot run — see the Auth section above), so this app no longer deploys via Twilio Serverless and `token.js`'s guard was dead code from this app's perspective. The patch file itself has since been deleted (it was left in place initially, out of scope for that cleanup, and later removed once confirmed unreferenced); `patch-package` and `postinstall` remain wired for the other three still-needed patches (`@material-ui+pickers`, `@mediapipe+tasks-vision`, `react-scripts`).

## Design patterns map (GoF sweep)

The codebase was swept for the classic GoF patterns; this is where they live now, so new code reuses them instead of re-growing the duplication. Where a pattern conflicted with an older note in this file, the pattern's rule wins (e.g. tiles keep `shallow` but assert on extracted leaf components or `.dive()`).

| Pattern | Where | Use it for |
| --- | --- | --- |
| Template Method | `server/teacherHandler.ts`; `Room/ShellLayout/RoomShellLayout.tsx` | a new teacher-only endpoint; a new desktop shell |
| Abstract Factory | `Room/roomShells.tsx` (`roomShellFactory`) | per-role shell + toolbar families (plain functions, not components) |
| Facade | `createApiClient`, `useParticipantTile`, `useScreenShareControl`, `useRecordingToggle`, `useTeacherNotificationApi`, `server/notificationInbox.ts`, `server/twilioGateway.ts` | one entry point over repeated SDK / HTTP / transaction ritual |
| Adapter | `toFaceFrame`, `useEmitterState`, `replaceUrlWithoutNavigation`, `useTeacherNotificationApi` | isolate an awkward third-party or optional API |
| Observer | `useEmitterState`, `useRosterEvents` | keep React in sync with SDK emitters |
| Mediator | `hooks/useClassDataChannel/classChannelBus.ts`, `Room/roomLayout.ts` | one place for cross-feature coordination (data-channel tracks, rail exclusion) |
| Strategy | `identitySuffixRole`, `resolveAttentionMode`, role toast policies (`useNotificationToasts`), `ROLE_THEME` in `IntroContainer` | swap behaviour/data by role or mode |
| Chain of Responsibility | `firstResolved` (`useInitialRole`, name seed); proctoring `DETECTORS`; `validateNewClass` | ordered rules where the first answer wins |
| Registry / table | `NOTIFICATION_KINDS`, `KIND_RULES`, `PROCTORING_KINDS`, `ATTENTION_LEVEL_STYLE`, `recordingStateView`, `presenceView`, `destinationResolvers`, `routes.ts` | replace parallel `switch`/`if` ladders; adding a case = adding a row |
| Null Object | `NO_CLASS_COMMANDS`, unavailable notification API, absent role-policy handlers | "not available" without `undefined` checks everywhere |
| Decorator | `withFetching` (`state/index.tsx`), `deleteQuietly` / `withUploadCompensation` | cross-cutting loading/error/cleanup around a call |
| Command | `leaveClass`, `useRecordingToggle().toggle`, `useScreenShareControl().toggleScreenShare` | an action reused by several controls |
| State | `FocusLostState`, `stepProctoring`, `classifyAttention`, `resolveScreen` | explicit states instead of sentinel numbers/flags |
| Factory | `createFirebaseAuthMiddleware`, `createTicketSigner`, `createWeightedIndex`, `createStorageSlot` | build configured collaborators; keep globals out of import time |
| Flyweight | `ATTENTION_LEVEL_STYLE` (frozen) | one shared style table |

Considered and **deliberately not done** (so nobody re-adds them): a `UserScope` Firestore facade (≈250 test fakes for little gain); a Singleton/Visitor/Bridge/Prototype/Iterator class hierarchy; splitting `VideoContext`; a shared 1 Hz ticker; `composeProviders`; an `AsyncStateView` component and `useRetryableCommand` (call sites differ in layout and are single-use); splitting `RoomNameScreen` into cards (no shared structure, 500 lines of shallow tests); a shared `classifyMediaError` and a shared initials helper (each surface recognises/derives different things on purpose); `joinGates`/`connectToRoom` (one gate; manual join and auto-rejoin differ in await ordering).

## Testing

- Unit tests: Jest + jsdom + `ts-jest`, with **Enzyme + enzyme-adapter-react-16** (React 16 stack). New tests should follow the existing Enzyme/`@testing-library/react-hooks` patterns rather than introducing a different runner.
- `src/setupTests.ts` polyfills `localStorage`, mocks `@twilio/video-processors` to silence "platform browser already set" warnings, and sets `document.fullscreenEnabled = true`.
- Cypress lives in `cypress/` and uses real Twilio resources — never enable it in automated CI without scoped credentials.
- **Server tests** live under `server/__tests__/` (e.g. `roomAccessGuard.test.ts`, `roomExists.test.ts`); client tests are colocated next to source as `*.test.ts`/`*.test.tsx`.
- **Tiles are `shallow`, shells are `mount`.** `ParticipantInfo`/`MainParticipantInfo` stay on `shallow` and assert on extracted leaf components (`RaisedHandBadge`, `ReconnectingOverlay`) — never `mount` them. The room shells (`ProfessorRoomShell`, `StudentRoomShell`) are rendered through `RoomShellLayout`/`CollapsibleRail` slots, so their tests `mount` (host markup only exists once the layout renders). Toolbar tests `.dive()` into `OverflowMenu` (`wrapper.find('OverflowMenu').dive()`) to reach the kebab and its items.
- **Hermetic page tests.** `useAppState` is mocked globally, so a page left mounted by an earlier test re-renders against a later test's mock — unmount wrappers in `afterEach` (see `RecordingViewerPage.test.tsx`). Hooks that take a loader (`useAsyncResource`, `useReloadableResource`) key their effect on the loader's identity: memoize it, and in tests don't create a fresh `jest.fn` per render if the call count matters.
- **Pure first.** New rules go in pure functions with an injected clock (`validateNewClass`, `resolveScreen`, `roomLayoutReducer`, `stepProctoring`, `classifyAttention`) and are tested without React.
- **prettier 1.19.1 gotcha:** the pre-commit hook (husky + lint-staged → prettier **1.19.1**) **cannot parse type-only re-export/import syntax** — `export type { X } from './y'` and `import type { ... }` will fail the hook. Barrel files (`index.ts`) must therefore import types **directly** from their source module rather than re-exporting them as `export type`. The `ProfessorRoomShell` barrel does this: `Room.tsx` imports the `ProfessorRightTab` type directly from `./ProfessorRoomShell/ProfessorRoomShell`, not from the barrel.
