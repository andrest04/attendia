# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Reference React app demonstrating Twilio Programmable Video + Twilio Conversations, scaffolded with Create React App (TypeScript). Ships with a local Express token server and a Twilio Serverless deployment path via the `@twilio-labs/plugin-rtc` CLI plugin. Requires Node.js >= 22.

## Commands

- `npm start` — runs the local token server (port 8081) and the CRA dev server (port 3000) concurrently. CRA proxies API calls to the token server via `package.json` `proxy`.
- `npm run dev` — CRA dev server only (no token server).
- `npm run server` — token server only (`ts-node` on `server/index.ts`, port 8081).
- `npm run build` — wraps `react-scripts build` via `scripts/build.js` to filter out CRA's "deploy via static server" hint (this app needs the token server).
- `npm run lint` — ESLint on `src` and `server` (config lives in `package.json` under `eslintConfig`, extends `react-app`).
- `npm run typescript:server` — type-checks the server only (`tsc --noEmit -p server/`). The client is type-checked by CRA on build/dev.
- `npm test` — Jest with `TZ=utc` and `jest.config.js` (jsdom environment, ts-jest, enzyme adapter for React 16).
- Run a single test: `npm test -- src/path/to/file.test.tsx` or `npm test -- -t "test name pattern"`.
- `npm run test:ci` — single-run, coverage, JUnit reporter; used in CI.
- `npm run cypress:open` / `npm run cypress:run` — E2E against a real deploy. **These hit live Twilio rooms and conversations and incur charges.**
- `npm run noisecancellation:krisp` — opt-in installer for the Krisp noise-cancellation plugin (copies WASM/weights into `public/noisecancellation`). Run once after `npm install`.
- `npm run storybook` — starts Storybook on port 6006.

`postinstall` copies `@twilio/video-processors` build artifacts into `public/virtualbackground` — required for virtual backgrounds to load at runtime.

## Architecture

### State source of truth
The Twilio Video SDK's `Room` object IS the state — there is no Redux. Components read from `room` and its child objects (which are EventEmitters) by subscribing through hooks. The pattern across `src/hooks/` is: `useState(room.someProperty)` + `useEffect` that attaches/detaches a listener to keep React in sync. When connected, `room` is exposed on `window.twilioRoom` for debugging; the chat client/conversation are exposed on `window.chatClient` / `window.chatConversation`.

### Provider tree (`src/index.tsx`)
```
MuiThemeProvider
└─ UnsupportedBrowserWarning
   └─ Router
      └─ AppStateProvider          // auth, settings, recording, gallery, captions, krisp
         └─ Switch (PrivateRoute / LoginPage)
            └─ VideoProvider       // Room, local tracks, screen share, backgrounds
               └─ ParticipantProvider
                  └─ ChatProvider  // Conversations client + active conversation
                     └─ AttentionProvider // classroom attention telemetry (currently mocked)
                        └─ App
```

`VideoProvider` and `ChatProvider` each own a piece of SDK lifecycle and expose it through context. Consumers use `useVideoContext` / `useChatContext` / `useAppState` rather than touching the SDKs directly.

### Two distinct hook layers (don't confuse them)
- `src/hooks/` — general-purpose hooks safe to call anywhere, any number of times (e.g. `useParticipants`, `useDominantSpeaker`, `useLocalAudioToggle`).
- `src/components/VideoProvider/use*` — internal hooks for the `VideoProvider` only. They manage singleton-ish lifecycle (the room, local tracks, screen share, background processor) and **must not be reused elsewhere**. The folder header comment in `VideoProvider/index.tsx` calls this out explicitly.

### Auth (firebase-only)
`firebase` is the only supported auth mode (as of the Feature-0 cleanup that dropped `passcode`/anonymous auth). `src/state/index.tsx` unconditionally calls `useFirebaseAuth()` (Google sign-in or email/password; the ID token is forwarded to the token server and verified by `server/firebaseAuthMiddleware.ts`). There is no more conditional-hook pattern gated on `REACT_APP_SET_AUTH` — `usePasscodeAuth` and the anonymous `getToken`-posts-directly-to-`/token` branch were deleted along with the `deploy:twilio-cli` script (Twilio Serverless Functions cannot run `firebase-admin`, so this app now only deploys as the Express server).

### Token server
`server/index.ts` is an Express wrapper that re-uses the serverless functions shipped inside `@twilio-labs/plugin-rtc/src/serverless/functions/*`. It exposes `/token` and `/recordingrules` (plus the Firestore-backed profile/reports/resources/classes routes), all guarded by `firebaseAuthMiddleware` unconditionally, and serves the built React app from `../build`.

### Connection options
`src/utils/useConnectionOptions/useConnectionOptions.ts` builds the `ConnectOptions` passed to `Video.connect`: dominant speaker detection, network quality API, and the bandwidth profile. Track priority is also adjusted dynamically — `VideoTrack` calls `track.setPriority('high')` on mount and resets on unmount so the main video area gets a high-resolution stream.

### Optional integrations to be aware of
- **Conversations / chat** is opt-out via `REACT_APP_DISABLE_TWILIO_CONVERSATIONS=true`.
- **Krisp noise cancellation** is opt-in (`npm run noisecancellation:krisp`); files are loaded from `public/noisecancellation/` at runtime.
- **Real-Time Transcriptions / captions** require enabling Real-Time Transcriptions in the Twilio Room settings; UI lives under `src/components/TranscriptionsOverlay`.
- **Virtual backgrounds** depend on the post-install copy of `@twilio/video-processors` into `public/virtualbackground/`.

## Classroom layer (built on top of the Twilio reference app)

A Spanish-language classroom domain has been built on top of the base Twilio reference app. The base SDK-as-state pattern is untouched; the classroom layer adds a role concept, role-specific room shells, attention telemetry, a classroom prejoin/auto-rejoin flow, a server-side access guard, and dev-only design surfaces. All in-room UI copy is Spanish.

### Roles & identity
- **Role IS the Twilio identity suffix — there is no server-side role field.** A teacher's display name gets the suffix `[Profesor]` appended at prejoin; that display name becomes the Twilio participant identity.
- `src/components/PreJoinScreens/classSessionTypes.ts` — domain helpers/types. `ClassSessionRole = 'teacher' | 'student'`, `TEACHER_DISPLAY_SUFFIX = '[Profesor]'`. `toClassSessionDisplayName(name, role)` appends ` [Profesor]` for teachers (idempotent, case-insensitive). `isTeacherIdentity(identity)` returns true iff the trimmed/lowercased identity **ends with** the suffix — this is the **only** role check used app-wide. Also: `toClassSessionRoomName` (slugify to ASCII kebab, strips accents, fallback `class-session`), `createClassSessionAccess` (builds `{roomName, joinCode, joinLink}`), `normalizeStudentJoinInputToRoomName` (extracts the room slug from a raw code or a full `/room/:name` URL). Committed; tests in `classSessionTypes.test.ts`.
- **This is a client-set value with NO server enforcement** — trivially spoofable, a UX guardrail, not a security boundary (see project memory "Room-access gate is a guardrail").

### Room shells & role routing
- `src/components/Room/Room.tsx` is the top-level layout switch (there is **no** `Room/index.tsx`; consumers import `../Room/Room`). It computes `const isTeacher = isTeacherIdentity(room?.localParticipant?.identity)` and picks: mobile → legacy `MobileGalleryView` / `MainParticipant`+`ParticipantList`; desktop teacher → `ProfessorRoomShell`; desktop student → `StudentRoomShell`. `GalleryView.tsx` performs the same `isTeacherIdentity` check to gate per-tile overlays.
- `src/components/Room/ProfessorRoomShell/` — three-rail desktop teacher layout (default export `ProfessorRoomShell` + `ProfessorToolbar` named export). Pieces: `SessionStatusBar.tsx` (dark bar: REC badge, session name · N estudiantes · elapsed clock via `useSessionElapsed.ts`), `GroupAttentionGauge.tsx` (pure SVG ring gauge, 0–100, color by level), `ProfessorToolbar.tsx` (audio/video/screenshare + Chat/Grabar/Proctoring/view-toggle chips + EndCallButton; the Chat chip shows an unread dot from `hasUnreadMessages` and toggles the chat tab via `chatOpen`/`onChatToggle` props; the view chip flips `useAppState().isGalleryViewActive` and advertises the TARGET view, like the legacy menu). The right rail has three tabs (`grupo` | `individual` | `chat`); the chat tab renders the `rightPanel` prop (Room.tsx passes the embedded `ChatWindow`). The left-rail roster shows **real room participants** (passed via the `participants` prop, professor included), decorated with attention badges only for identities the attention pipeline knows about; the **Individual tab stays on (mocked) attention data** — it is the analytics surface, not presence. The Grabar chip drives **real recording** via `useAppState().updateRecordingRules` + `useIsRecording` (room `recordingStarted/Stopped` events); it only renders for room types that support recording rules (not `peer-to-peer`/`go`, same gate as the legacy menu). Proctoring is still a **local-only stub** (US30); the hands-raised queue is fed by `useRaiseHand` (real DataTrack transport). `useSessionElapsed` counts from **mount** time, not room connect time (stub).
- `src/components/Room/StudentRoomShell/` — three-column desktop student layout (default export + `StudentRoomToolbar`). Purely presentational/stateless; receives everything via props from Room.tsx. The right rail is **chat-only** (a single always-active Chat tab) rendering the **real** `<ChatWindow embedded isVisible />` (the `embedded`/`isVisible` props drop its own header and obey the prop instead of the global open flag). The student-facing "Mi Atención" panel was **removed entirely** (product decision; `AttentionPanel` and `ToggleAttentionButton` no longer exist, and `isAttentionPanelOpen` is gone from ChatContext). There is **no** `StudentChatPanel` mock — wireframes were matched by restyling real components. The student sees **their own video as a regular gallery tile** (professor parity); the old student-only PiP self-view was removed. `StudentRoomToolbar` carries the same view-toggle (gallery ↔ speaker) the professor has via `ToggleViewButton` (`src/components/Buttons/ToggleViewButton/`), so students are no longer locked into one view. `useShellNotifications.ts` builds an in-memory, **capped (last 3), non-persisted** feed of **classmate** join/leave events only — everything role-important (the professor's presence, recording, the local turn, raise-hand) is surfaced as transient **toasts** instead (see *In-room notifications & raise-hand* below). Raise-hand signaling runs over a Twilio **LocalDataTrack** (`src/hooks/useRaiseHand/useRaiseHand.ts`) — real transport, no longer a local stub.
- When a desktop shell is active, Room.tsx collapses the legacy sidebar grid column (`classes.desktopShell`) to avoid an empty gutter; the legacy `ChatWindow` drawer only renders on mobile.

### Attention system
- **REAL CV pipeline, graduated from the lab, OFF by default.** Attention used to be 100% mocked; it is now a real on-device computer-vision pipeline, gated behind the env flag **`REACT_APP_ENABLE_ATTENTION_CV`** (default OFF → mock fallback). The provider goes **live** only when the flag is `'true'` AND a Room is connected AND the device is desktop; otherwise it falls back to `mockAttentionData`. The whole thing was built by graduating the former `/lab/attention` spike (since removed — see Dev-only section) into the real flow in layers: heuristics → capture → transport → provider swap → consent.
- `src/utils/attentionHeuristics.ts` — pure, deterministic, tested CV heuristics (gaze via iris landmarks, head pose pitch/yaw/roll, blink, focus-lost state machine, rolling-window scoring, `computeLabAttentionIndex(eyes,head)` = 4/7·eyes + 3/7·head — posture excluded). Graduated out of `src/components/lab/`; keep it pure (no MediaPipe/React/IO).
- `src/hooks/useAttentionCapture/` — runs MediaPipe **FaceLandmarker** over the Twilio **local** video track at 1 Hz (`SAMPLE_INTERVAL_MS`), CDN WASM, `numFaces:2` for multiface. Returns `{capture,index,components{eyes,head},faces,multiface}`; stays inactive (no MediaPipe load) without a track. Frames go to an offscreen canvas and are discarded — nothing leaves the device. Full WASM/GPU dispose on cleanup.
- `src/hooks/useAttentionTelemetry/` — singleton `LocalDataTrack` (structural copy of `useRaiseHand`) broadcasting each participant's own snapshot at 1 Hz and aggregating remotes → `RemoteAttention[]` (`{identity,index,multiface,faces}`). Coexists with raise-hand: both listen to all data tracks but filter by message `type`. Only the number travels, never an image.
- `src/components/AttentionProvider/index.tsx` — calls capture+telemetry, assembles **live** `AttentionData` (participants from telemetry, real group average, real accumulated timeline, proctoring from multiface, self eyes+head with **posture carried as `-1` = not-measured sentinel**) or spreads `mockAttentionData`. `attentionLevel(score)` ranges lowMax=40/mediumMax=70. `useAttention()` throws outside the provider. Live index uses `computeLabAttentionIndex`; `attentionFormula.ts` `computeAttentionIndex` (clamp(0.40·eyes + 0.30·posture + 0.30·head)) now serves **only the mock fallback** until posture is a measured signal. There is **no** `enabled`/`setEnabled` — students have no control (consent is the gate instead).
- `src/components/AttentionProvider/mockAttentionData.ts` — deterministic mock (no `Math.random`/`Date.now`): `groupAttention=72`, `attentionThreshold=60`, 11-point timeline, 5 participants, 2 proctoring alerts, `source:'mock'`. Still the **fallback** value when the pipeline is off. `types.ts` holds all contracts.
- Three consumption paths: (1) **group gauge** — `ProfessorRoomShell` reads `useAttention()` and feeds `GroupAttentionGauge` + recharts timeline + roster badges + proctoring feed (shows a "Datos simulados — pipeline CV pendiente" tag when `source==='mock'`; Individual-tab bar widths use a level→percent lookup 85/60/35, not the raw index); (2) **per-tile overlay** — `GalleryView.tsx` reads `AttentionContext` defensively (tolerates null in tests), builds an identity→{level,multiface} Map **only when teacher**, passes `attention` through `Participant.tsx` to `ParticipantInfo.tsx` (corner badge + multiface flag; local tile never overlaid). Note `GalleryView` now includes the local participant as a regular tile for **everyone** (students reached professor parity; the student-only exclusion was removed). All consumption is **professor-facing**: the student "Mi Atención" panel (`AttentionPanel` + `ToggleAttentionButton` + `isAttentionPanelOpen` in ChatContext) was removed entirely (2026-06-12), and so was the `enabled`/`setEnabled` analysis-pause state — **students have no attention UI and no control over the analysis** (product decision; if a privacy control ever returns, it is a new feature, not a revert). AttentionProvider still nests inside ChatProvider for historical reasons only (the flag that required it is gone); the nesting is vestigial but harmless.
- The professor's report is **view-only** and **opens in a NEW TAB** (not an in-room overlay — `AttentionReportOverlay` was removed 2026-07-04). The Grupo-tab "Ver reporte" button (eye icon) calls `ProfessorRoomShell.handleOpenReport`, which snapshots the live `useAttention()` data into `localStorage` via `saveReportSnapshot` (`src/components/AttentionReport/reportSnapshot.ts`, key `attendia-report-snapshot`, shared cross-tab — `sessionStorage` is NOT) and `window.open('/report', '_blank', 'noopener')`. A new tab is a separate document with no room/context, so `/report` (`src/components/ReportPage/ReportPage.tsx`, plain route outside `PrivateRoute`/`VideoApp`) reads the point-in-time snapshot and renders the shared `AttentionReportView` — which is why that view is a pure data-via-props component. `buildReportViewData.ts` is the shared normalizer (also used by `/history`). The snapshot is static by design (a report IS a snapshot); it never updates live. `/report` is registered as a fallback asset in the plugin-rtc `helpers.js` patch (same as `/security`/`/manual`) so a hard GET doesn't 404 on the Twilio deploy. There are no download/export affordances (PDF/Excel/CSV exporters and the `jspdf`/`jspdf-autotable`/`xlsx` deps were removed, 2026-06-12).

### In-room notifications & raise-hand
- **Toasts via `notistack`** (pinned to **`notistack@1.0.10`** — v2/v3 require MUI v5, this app is MUI v4). `SnackbarProvider` (maxSnack 3, autoHide 4s, top-right, dense) wraps `<App/>` inside `VideoApp` (`src/index.tsx`), so toasts are in-room only and inside the MUI theme.
- `src/hooks/useNotificationToasts/useNotificationToasts.ts` fires a **role-curated** policy so the same raw event surfaces only where it matters. **Student** toasts: professor joins/leaves, "es tu turno", recording on/off. **Professor** toasts: students joining/leaving and raising their hand. Classmate join/leave goes to the student panel (`useShellNotifications`, capped to last 3), NOT toasts; the student's own raise-hand is not toasted (redundant). Prev-value refs are seeded on mount so already-present state never toasts on first render. The old MUI `<Snackbar>` "es tu turno" cue was migrated into this hook. Any test that renders `Room` must `jest.mock('notistack')` (Room calls `useSnackbar`).
- **Raise-hand badge** — when a participant raises their hand, a hand badge (white circle + dark `PanToolIcon`) shows in the **bottom-right of their tile**. `useRaiseHand` stays a SINGLETON (one `LocalDataTrack`) called once in `Room.tsx`; Room derives a `Set<string>` of raised identities (remote `raisedHands` + local when `isHandRaised`) via `buildRaisedHandIdentities` and provides it through `RaisedHandsContext` (`src/hooks/useRaiseHand/raisedHandsContext.ts`). `ParticipantInfo.tsx` and `MainParticipantInfo.tsx` read it via the `useRaisedHand(identity)` hook (extracted so component tests mock it and stay on `shallow` — do NOT `mount` those tiles; they fire real `useTrack`/`useScreenShareParticipant` effects). Default empty set → tiles render fine without a provider.

### Prejoin session entry & auto-rejoin
- Replaces Twilio's "type a room name" lobby with a classroom prejoin flow. `src/components/PreJoinScreens/PreJoinScreens.tsx` resolves `initialRole` in priority order: deep-link `URLRoomName` → student; else `location.state.preJoinRole` (set by LoginPage) → that role; else teacher. Two-step state machine (roomName → deviceSelection). `RoomNameScreen.tsx` renders two distinct UIs by role (teacher "Crear sesión de clase"; student "Unirme a sala existente"). `goToDeviceSelection` `replaceState`s the URL to `/room/:name` (skipped on `twil.io` origin / Storybook) so a later refresh can match for auto-rejoin.
- **Auto-rejoin (committed):** a full page refresh destroys the Twilio Room (the source of truth) and would drop the user back to the lobby. `rejoinSession.ts` persists `{roomName, identity}` in **`sessionStorage`** (key `twilio-video-rejoin-session`; survives refresh, tab-scoped, dies on tab close); all reads/writes swallow storage errors. `getResumableSession(urlRoomName)` only resumes when the stored `roomName === urlRoomName` (stops a stale tab hijacking a fresh deep link). `useAutoRejoin.ts` seeds `isRejoining` synchronously (no lobby flash), then on mount re-acquires local media (non-fatal on failure), fetches a fresh token for the saved identity, `videoConnect`, and `chatConnect` (unless `REACT_APP_DISABLE_TWILIO_CONVERSATIONS==='true'`). It also watches `AppState.error` because `useRoom`'s connect **resolves (not rejects)** on SDK failure and surfaces via app error state — don't "simplify" this into a try/catch.
- Lifecycle: `DeviceSelectionScreen.handleJoin` calls `saveRejoinSession({roomName, identity:name})` after a successful token fetch (`name` already includes the teacher suffix); `EndCallButton.handleEndCall` calls `clearRejoinSession()` before `room.disconnect()` so an intentional "Salir" does **not** auto-rejoin, whereas a refresh (disconnects via `beforeunload`, not this handler) keeps the session and reconnects. Files: `rejoinSession.ts`, `rejoinSession.test.ts`, `useAutoRejoin.ts`, plus the changes to `PreJoinScreens.tsx`/`.test.tsx`, `DeviceSelectionScreen.tsx`, `EndCallButton.tsx`, and `src/state/*` are committed.
- **getToken contract changed (committed):** all three auth-mode `getToken` variants now **reject** on a non-OK server response, preferring `error.explanation > error.message > statusText` (the room-access guard's localized Spanish message). The outer wrapper in `state/index.tsx` both `setError()`s (app ErrorDialog) **and** re-rejects, so callers must handle the rejection (`DeviceSelectionScreen` adds `.catch(()=>{})`). Note `MediaErrorSnackbar` handles only getUserMedia/device errors and its copy is still **English** (inconsistent with the Spanish lobby).
- **Attention-analysis consent gate (committed):** when `REACT_APP_ENABLE_ATTENTION_CV==='true'`, a **student** (never a teacher) must accept `AttentionConsentModal` before joining — the legal gate for the real CV pipeline. `DeviceSelectionScreen.handleJoin` is split into `doJoin()` (the real token fetch + connect) and a gate: `cvEnabled && !isTeacherIdentity(name) && !hasConsent(roomName)` → opens the modal (no backdrop/escape dismiss); "Aceptar y unirme" → `saveConsent` + `doJoin`, "Volver" → stays on device selection (no join). `attentionConsent.ts` persists consent in `sessionStorage` (key `twilio-video-attention-consent`, room-scoped, error-swallowing, mirrors `rejoinSession`) so auto-rejoin doesn't re-prompt. The modal copy lists only what is actually measured (gaze + head, **not** posture) and only mounts when the flag is on; flag off → no prompt, normal join. Product decisions: prejoin-time, accept-or-go-back, **fixed at entry** (no in-room revocation UI).

### Server-side room-access guard
- **Honest-flow gate on `POST /token` (committed).** Twilio creates a room on demand, so whoever requests a token first would create+enter it. The guard stops a student from silently opening a session the teacher never started: a student requesting a token for a room that is not already open gets **HTTP 403** instead of implicitly creating it. Teachers are always allowed; this is **explicitly a UX guardrail, NOT a security boundary** (role is the client-set identity suffix).
- `server/index.ts` wires `app.all('/token', authMiddleware, createRoomAccessGuard(roomExists), tokenEndpoint)`. `/recordingrules` gets `authMiddleware` but **not** the room guard.
- `server/roomAccessGuard.ts` — `createRoomAccessGuard(roomExists)` + a server-side mirror of `isTeacherIdentity`/`TEACHER_DISPLAY_SUFFIX` (**must be kept in sync** with `classSessionTypes.ts`; no shared module). Passes through without checking when `create_room===false`, identity is a teacher, or `room_name` is missing; otherwise awaits `roomExists(room_name)`: exists → `next()`; missing → 403 (Spanish explanation); thrown error → 503 (**fail-closed**). Missing `create_room` is treated as room-creating, so students are gated by default.
- `server/roomExists.ts` — `createRoomExists(twilioClient)`; calls `twilioClient.video.rooms(name).fetch()` (Twilio REST, not plugin-rtc). Success → true; `status===404` → false (the freed uniqueName **is** the "class is closed" signal); any non-404 error rethrown → guard 503. `server/createExpressHandler.ts` exports the shared `twilioClient`. Tests: `server/__tests__/roomAccessGuard.test.ts`, `server/__tests__/roomExists.test.ts`.
- **Deploy parity (removed):** this repo used to also ship `patches/@twilio-labs+plugin-rtc+0.9.0.patch`, porting the same guard into plugin-rtc's serverless `token.js` for the `deploy:twilio-cli` Twilio Serverless deploy path. That script was removed (Feature 0: firebase-only auth needs `firebase-admin`, which Twilio Serverless Functions cannot run — see the Auth section above), so this app no longer deploys via Twilio Serverless and `token.js`'s guard was dead code from this app's perspective. The patch file itself has since been deleted (it was left in place initially, out of scope for that cleanup, and later removed once confirmed unreferenced); `patch-package` and `postinstall` remain wired for the other three still-needed patches (`@material-ui+pickers`, `@mediapipe+tasks-vision`, `react-scripts`).

## Testing

- Unit tests: Jest + jsdom + `ts-jest`, with **Enzyme + enzyme-adapter-react-16** (React 16 stack). New tests should follow the existing Enzyme/`@testing-library/react-hooks` patterns rather than introducing a different runner.
- `src/setupTests.ts` polyfills `localStorage`, mocks `@twilio/video-processors` to silence "platform browser already set" warnings, and sets `document.fullscreenEnabled = true`.
- Cypress lives in `cypress/` and uses real Twilio resources — never enable it in automated CI without scoped credentials.
- **Server tests** live under `server/__tests__/` (e.g. `roomAccessGuard.test.ts`, `roomExists.test.ts`); client tests are colocated next to source as `*.test.ts`/`*.test.tsx`.
- **prettier 1.19.1 gotcha:** the pre-commit hook (husky + lint-staged → prettier **1.19.1**) **cannot parse type-only re-export/import syntax** — `export type { X } from './y'` and `import type { ... }` will fail the hook. Barrel files (`index.ts`) must therefore import types **directly** from their source module rather than re-exporting them as `export type`. The `ProfessorRoomShell` barrel does this: `Room.tsx` imports the `ProfessorRightTab` type directly from `./ProfessorRoomShell/ProfessorRoomShell`, not from the barrel.
